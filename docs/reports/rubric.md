## Datos de la actividad

- **Curso:** Programación Avanzada A1 — Universidad de La Guajira.
- **Proyecto:** aplicación real en Python que resuelva un problema concreto; tema libre.
- **Grupos:** de 2 a 4 personas (grupos de 1 requieren autorización).
- **Entrega:** repositorio Git + sustentación presencial.
- **Fecha límite:** miércoles 25 de noviembre de 2026, 12:00 m. (hora Colombia).
- **Sustentación:** miércoles 25 de noviembre, 10 minutos por grupo (demo en vivo + preguntas individuales).
- **Restricción técnica:** no se aceptan aplicaciones de solo consola; debe existir una interfaz o punto de acceso real.
- **IA:** permitida sin restricción, tanto para desarrollar como dentro de la app.

## Entregables

1. Enlace al repositorio Git enviado al docente antes del plazo.
2. `README.md` con nombre del proyecto, descripción del problema, instrucciones de instalación y ejecución, uso de IA y nombres de todos los integrantes.
3. Sustentación presencial de 10 minutos.

## Rúbrica (5.0 puntos)

| Criterio | Puntos | Peso | Nivel sobresaliente |
| --- | ---: | ---: | --- |
| 1. Utilidad real y alcance | 1.0 | 20 % | Problema real y específico; usuario claro; alcance ambicioso pero alcanzado; alguien no técnico podría usarlo |
| 2. Funcionalidad y ejecución | 1.5 | 30 % | App sin errores, demo fluida, datos persistentes, errores visibles y al menos 3 funcionalidades completas |
| 3. Calidad técnica del código | 1.0 | 20 % | Código limpio, modular, framework bien usado, separación de responsabilidades, `.env` para secretos, sin código muerto |
| 4. Sustentación individual | 1.0 | 20 % | Cada integrante explica su parte y el proyecto, responde preguntas técnicas y navega el código en vivo |
| 5. Repositorio y documentación | 0.5 | 10 % | Repo público, commits de todos, README completo, dependencias y `.gitignore` correctos |

### Niveles por criterio

- **Criterio 1:** sobresaliente 1.0 / satisfactorio 0.7 / básico 0.4 / no cumple 0.0.
- **Criterio 2:** sobresaliente 1.5 / satisfactorio 1.0 / básico 0.5 / no cumple 0.0.
- **Criterio 3:** sobresaliente 1.0 / satisfactorio 0.7 / básico 0.4 / no cumple 0.0.
- **Criterio 4:** sobresaliente 1.0 / satisfactorio 0.7 / básico 0.4 / no cumple 0.0; se evalúa por persona.
- **Criterio 5:** completo 0.5 / parcial 0.25 / ausente 0.0.

## Políticas de entrega

- **IA:** permitida. Si en la sustentación se evidencia que un integrante no comprende el código, su nota del criterio 4 será 0.0.
- **Commits:** todos los integrantes deben tener commits. Un repositorio con commits de una sola persona puede generar revisión de autoría. Se piden mínimo 5 commits descriptivos por integrante.
- **Variables sensibles:** claves, contraseñas y tokens no deben subirse. Usar `.env` con `python-dotenv`.
- **Dependencias:** `requirements.txt` o `pyproject.toml`.
- **`.gitignore`:** sin `.env`, `__pycache__` ni archivos temporales.
- **Atrasos:** no se reciben entregas después del 25 de noviembre de 2026 a las 12:00 m.
- **Preguntas al docente:** hasta el 18 de noviembre de 2026.
